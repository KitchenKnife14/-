## 2. Структура таблиц: что сравнили

Сопоставлены определения TABLES в Code.gs на a7f105d и текущей ispravleniya: **совпадают текстуально все 15 таблиц и порядок их столбцов**. Отдельный служебный лист _auth содержит шесть полей: id, email, salt, password_hash, display_name, created_at. Он не входит в TABLES, должен оставаться скрытым и приватным.

15 таблиц: profiles, families, family_members, categories, accounts, transactions, recurring_payments, budgets, goals, goal_contributions, planned_purchases, monthly_plans, notifications, telegram_links, telegram_link_codes.

Это **сравнение исходников**, а не снимок фактических заголовков основной Google-таблицы. Нет оснований менять имена или порядок столбцов только из-за этих исправлений. Реальную структуру нужно проверить в отдельной копии перед публикацией.

## 3. Правила обработки старых строк

| Ситуация в существующих данных | Поведение текущего кода / совместимость | Действие до релиза |
| --- | --- | --- |
| Заголовки совпадают с TABLES | Чтение допускается по заданной схеме; прочие проверки прав/типов действуют | Подтвердить auditBackupStructure() на приватной копии и сохранить только структурную сводку |
| Отсутствует завершающий столбец (например, старые transactions или recurring_payments до responsible_user_id) | Read-only запрос отклоняет неготовую схему без автодобавления. В write-пути возможно добавление **только точного суффикса** существующих заголовков | Не допускать неявного обновления основной таблицы. Зафиксировать точный diff, протестировать изменение **в отдельной TEST-копии**, затем согласовать миграцию до Production |
| Листы отсутствуют, заголовки переставлены/повреждены | Read-only отказывает без создания листа; небезопасный заголовок write-путь не исправляет автоматически | Остановить публикацию, сохранить копию и провести отдельную диагностику, не удалять и не переставлять строки |
| Старые учетные записи _auth с прежним SHA-256 hash | Вход сохраняет поддержку legacy hash; при успешном входе код пытается заменить его на PBKDF2. Физический row index сохраняется через пустые строки | Тестировать только на копии с синтетическими credential, не выводить содержимое _auth. Проверить вход существующего пользователя отдельно и с его согласия |
| Суммы в копейках как текст | Строки из целого безопасного числа нормализуются при чтении; нецелые, слишком большие и некорректные строки не следует молча округлять | В копии сравнить тип/разрядность кооперативно; не выполнять массовое изменение сумм |
| Даты/время, ранее превращённые Sheets в Date | normal_ использует timezone таблицы и тип столбца, сохраняет формат времени/дат при чтении. TEXT_COLS задаёт текстовый формат для новых/обслуживаемых столбцов | В копии проверить даты конца месяца и реальный timezone, не переписывать исторические operation_date |
| accounts/categories с пустым archived | Для чтения пустое значение трактуется как false | Не проставлять значения массово в основной таблице |
| Старые связи family_members, многократное членство, несогласованный created_by | Доступ теперь ограничен первой активной family_members пользователя; created_by не открывает дополнительную семью. Telegram-привязки также требуют активную семью | Сверить legacy связи на **копии**; при обнаружении неверной семьи остановить публикацию и отдельно согласовать исправление связей |
| Семья, у которой нет действующего владельца/участника | Отчёт восстановления TEST 20.11 выявил такой **исторический** случай в TEST-источнике, но это **не доказательство** проблемы в Production | Не добавлять членство автоматически и не удалять семью; проверить принадлежность в приватной копии, запросить отдельное решение владельца |
| Несовпадающие категории у старой операции | Тесты допускают несвязанные правки без скрытой перестройки старых категорий; новые действия должны проходить проверку связей | Не переназначать категории и старые операции без явной согласованной миграции |
| Ревизии и временные сессии в Script Properties | Свойства session:*, loginfail:*, table_revision:v2:*, telegram:update:* не являются частью содержимого Google Sheets | Не экспортировать/восстанавливать секреты и временные ключи из копии; после восстановительной процедуры ожидать повторный вход и обновление кэша |

## 4. Обязательная последовательность приёмки без изменения Production

1. Сначала выполнить уже подготовленный **M-04** на существующих TEST Script, TEST spreadsheet и TEST deployment после положительной проверки guard. Использовать два точно закреплённых исходника из TEST-ENV-READINESS.md, сохранить предыдущую TEST version, выполнить четыре runtime probes с cleanup=PASS. Не запускать тесты на Production.
2. Только в согласованном отдельном процессе подготовить свежую **приватную копию** Production spreadsheet и подтвердить разрешение владельца. Никогда не запускать приёмочные операции прямо на основной таблице.
3. На **копии** выполнить read-only auditBackupStructure() из привязанного к ней TEST-проекта (при необходимости настроенного отдельно), сверить все 16 листов с _auth, заголовки, порядок, строковые ID, число записей, hidden-state и timezone. Отчёт не должен содержать паролей, хешей, текстов операций или сумм.
4. До любой записи сравнить на копии исторические строки и связи: profiles/families/family_members, owner_user_id, category_id, account_id, responsible_user_id, старые hash и dates. Отдельно отметить orphan/duplicate memberships; **не чинить автоматически**.
5. Если схема требует добавления столбца, подготовить **отдельный миграционный diff**, резервную копию, тест на копии и откат. Без согласования изменения в Production запрещены.
6. После успешной TEST-приёмки проверить существующие бизнес-сценарии двух участников, повторный вход, фильтры, регулярные платежи и Telegram только в TEST. Проверку физических iPhone/Safari сохранить отложенной до дома.
7. Перед Production выпуском перепроверить фактический Vercel Production deployment, Apps Script deployment version и backend URL, согласовать compatibility/release/rollback, резервную копию, права и **получить отдельное разрешение**. Если любой контроль не пройден — остановиться.
