# Сквозная проверка идемпотентности в отдельном Apps Script deployment

Только отдельная копия Google-таблицы и отдельный тестовый Apps Script deployment. Не обращаться к production и не использовать основную таблицу.

## Что проверяется
1. Два параллельных HTTP POST с одинаковыми ID и payload для goal_contributions.
2. Повторный POST с тем же ID после намеренного игнорирования предыдущего результата.
3. Ровно одна сохранённая строка и однократное увеличение saved_kopecks.
4. Удаление только созданного тестом пополнения и восстановление исходного баланса.

UrlFetchApp.fetchAll отправляет два запроса одновременно к реальному deployment. «Потерянный ответ» моделируется повтором после игнорирования предыдущего результата; это не физическая симуляция обрыва TCP после commit.

## Подготовка только на тестовой копии
1. Создать копию таблицы и добавить в название TEST или ТЕСТ.
2. Создать отдельный Apps Script project, привязанный к копии, и отдельный Web App deployment.
3. В тестовой семье создать цель и получить token тестового пользователя.
4. Добавить файл tests/gas/IdempotencyConcurrencyTest.gs в отдельный тестовый Apps Script project.
5. В Script Properties тестового проекта задать:
   - IDEMPOTENCY_TEST_WEB_APP_URL — URL вида https://script.google.com/macros/s/TEST_DEPLOYMENT_ID/exec;
   - IDEMPOTENCY_TEST_TOKEN — token тестового пользователя;
   - IDEMPOTENCY_TEST_FAMILY_ID — ID тестовой семьи;
   - IDEMPOTENCY_TEST_GOAL_ID — ID тестовой цели;
   - IDEMPOTENCY_TEST_CONFIRM — строго ISOLATED_TEST_ONLY.
6. Убедиться, что тестовый Web App использует backend из ветки исправлений и подключён только к тестовой копии.
7. Запустить runIdempotencyConcurrencyTest и проверить журнал выполнения.

## Защитные ограничения
- Активная таблица обязана иметь TEST/ТЕСТ в названии.
- URL проверяется на стандартный Apps Script Web App формат и известный production deployment ID.
- Без отдельного подтверждения запросы не отправляются.
- ID пополнения уникален для каждого запуска; удаляется только эта запись.
- При ошибке очистки выводится ID для ручной проверки; другие строки не удалять.
- Не переносить тестовый runner в production Apps Script project.

Пока тест не выполнен на изолированной среде, конкурентная идемпотентность остаётся непроверенной. Этот этап не требует изменений основной таблицы или deployment.
