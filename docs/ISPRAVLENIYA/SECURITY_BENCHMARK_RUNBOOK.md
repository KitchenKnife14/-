# Замер PBKDF2 на тестовом Apps Script

Статус: инструменты подготовлены; реальные измерения ещё не выполнялись.

## Цель

Сравнить стоимость текущих 30 000 итераций PBKDF2-HMAC-SHA256 с 600 000 итерациями (ориентир OWASP) именно в среде Google Apps Script V8. Не менять алгоритм и существующие хеши до завершения замеров.

## Безопасные ограничения

- Запускать только в отдельном тестовом Apps Script проекте; не использовать Production deployment или основной проект.
- В проекте должны находиться актуальный Code.gs из ветки ispravleniya и файл PBKDF2_RUNTIME_DIAGNOSTICS.gs.
- Диагностическая функция использует только синтетические пароль/соль, не читает и не меняет Sheets, _auth, Script Properties или пользовательские credentials.
- Не запускать параллельно несколько benchmark execution.
- Не менять PW_ITERATIONS на основании Node.js/CI замера: нужен результат Google Apps Script.

## Порядок измерения

1. Открыть отдельный тестовый Apps Script V8 проект, не связанный с Production deployment.
2. Убедиться, что в проект перенесены актуальные Code.gs и PBKDF2_RUNTIME_DIAGNOSTICS.gs из ispravleniya. Диагностический файл использует pbkdf2Hex_() из Code.gs, поэтому оба файла должны быть в одном проекте.
3. В списке функций выбрать runPbkdf2RuntimeDiagnostics и нажать Run.
4. Дождаться завершения. Один запуск прогревает JS-путь синтетическим вводом, затем делает 5 измерений для 30 000 итераций и 3 измерения для 600 000 итераций. В Execution log выводится один JSON-объект с отдельными временами, минимумом, медианой и максимумом.
5. Сохранить только JSON-результат измерений и дату/время в закрытый операционный журнал. В результат не входят пароль, соль или digest.
6. При необходимости повторить весь запуск ещё один раз отдельно, не параллельно. Сравнить медианы; если результаты сильно расходятся, провести дополнительный запуск после паузы.
7. После runtime benchmark отдельно оценить реальный вход на тестовом аккаунте на desktop и iPhone. Не использовать реальные пользовательские пароли для benchmark.
8. Проверить лимиты GAS и задержку при нескольких одновременных тестовых входах на отдельных тестовых аккаунтах.
9. Не менять PW_ITERATIONS автоматически. Решение о сохранении 30 000 или повышении work factor принимать только после фактического времени GAS, оценки UX и параллельных входов.

## Что остаётся открытым

- Реальное время PBKDF2 на Google Apps Script.
- UX входа на мобильном и desktop.
- Проверка лимитов выполнения и нескольких одновременных входов.
- Решение о сохранении 30 000 или повышении work factor.

Успешный CI и локальный Node benchmark не закрывают эти пункты.
