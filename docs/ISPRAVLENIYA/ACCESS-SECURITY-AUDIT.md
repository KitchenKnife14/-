# Аутентификация и доступ — практический объём проекта

> Обновлено: 2026-11-17. Рабочая ветка: `ispravleniya`.

## Цель

Family Cash — небольшой семейный бюджет для двух участников, а не высокорисковая корпоративная система. Требуется обычная понятная авторизация, чтобы каждый входил по email и паролю, а семейные данные не смешивались с чужими.

## Оставляем

- регистрация и вход по email и паролю;
- обычная серверная сессия;
- доступ к общим данным только участникам соответствующей семьи;
- возможность выйти из аккаунта;
- простое восстановление пароля по email — желаемая функция, пока не реализована.

## Не развиваем без конкретной причины

- усложнённые антибрутфорс-механизмы для кодов приглашения и Telegram;
- дополнительные уровни проверки и сложные security-инструменты;
- бесконечные аудиты гипотетических сценариев атак;
- CSP и дополнительные заголовки как отдельный большой проект, если нет выявленной практической проблемы.

## Текущее состояние кода

- Backend и интерфейс регистрации требуют пароль длиной минимум 8 символов.
- Вход выполняется по email и паролю.
- Разделение семейных данных остаётся обязательной базовой функцией приложения.
- Дополнительные меры для 32-символьных invite/Telegram кодов и лимитирования их попыток были удалены как избыточные; используются прежние коды.
- Восстановление пароля пока отсутствует. Его предлагается сделать простым потоком: пользователь вводит email, получает письмо со ссылкой/кодом, задаёт новый пароль. Реализацию нужно проверить в TEST GAS; для отправки писем потребуется разрешение Apps Script MailApp и проверка фактической доставки.

## Следующий порядок

1. Выполнить CI/регрессионные тесты после упрощения минимальной длины пароля и удаления дополнительных security-механизмов.
2. Проверить обычные сценарии регистрации, входа, выхода и доступа двух участников в TEST GAS.
3. Реализовать восстановление пароля по email без лишних дополнительных шагов.
4. После тестирования обновить только TEST GAS. Production не менять без отдельного разрешения пользователя.
