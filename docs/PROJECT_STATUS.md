# Состояние проекта — «Бюджет для двоих»

Дата фиксации: 2026-11-02

## Целевая архитектура
- Frontend: React 18 + TypeScript + Vite + Tailwind CSS + React Router.
- Хранилище: Google Sheets.
- Backend/API: Google Apps Script Web App.
- Frontend hosting: Vercel.
- Язык: русский; валюта: ₽; timezone: Europe/Moscow.
- Приложение рассчитано на двух пользователей одной семьи.

## Репозиторий
- Репозиторий: https://github.com/KitchenKnife14/-
- Рабочая линия Google Apps Script: `audit/backend-upsert-guards`.
- Ветка должна проверяться через GitHub перед каждым новым этапом; этот документ не фиксирует динамический HEAD, потому что ветка меняется с коммитами.
- Production и основная ветка не должны изменяться в ходе обычной разработки.

## Основные файлы
- `src/lib/googleSheets.ts` — клиентский адаптер Apps Script API.
- `google-apps-script/Code.gs` — Web App backend.
- `tests/apps-script.test.cjs` — API/auth/backend regression tests.
- `tests/account-balances.test.cjs` — расчёт остатков.
- `src/context/AuthContext.tsx` — auth/family state.
- `src/components/Layout.tsx` — основная оболочка и навигация.
- `src/pages/` — страницы финансового приложения.
- `src/index.css` — общие стили и дизайн-система.
- `.env.example` — пример конфигурации адреса Apps Script.

## Уже имеющаяся функциональность
- Регистрация, вход и сессионная авторизация реализованы в Apps Script.
- Семейное пространство, членство семьи и приглашение второго пользователя реализованы.
- Основные таблицы: profiles, families, family_members, categories, accounts, transactions, recurring_payments, budgets, goals, goal_contributions, planned_purchases, monthly_plans, notifications.
- Frontend использует API-адаптер с тайм-аутом, batching, объединением одинаковых запросов, read cache и инвалидацией кэша при записях.
- Реализованы операции с доходами/расходами, счетами/переводами, категориями, бюджетами, целями, регулярными платежами, покупками, планированием, календарём, отчётами, аналитикой и уведомлениями.
- В Apps Script ведутся счётчики чтений/записей и timing logs для диагностики.
- В проекте уже есть тесты Apps Script API и расчёта остатков.

## Изменения, начатые в рабочей ветке
В ходе текущего инженерного этапа:
- начата оптимизация разделения read/write в Apps Script;
- добавлена проверка revision marker для обнаружения чтения во время записи;
- generic CRUD partial failures должны блокировать чтение до проверки, а RPC/auth/family actions с rollback/idempotency не должны получать ложную блокировку;
- реализуется поддержка отрицательных goal contribution как снятий, но итоговая сумма движений по цели не может быть меньше нуля;
- добавлены проверки денежной целочисленной семантики;
- усиливается экранирование пользовательского текста перед записью в Google Sheets;
- добавляются подтверждения удаления целей, бюджетов, запланированных покупок и расписаний;
- исправляется иконка домашней навигации;
- добавлена начальная визуальная основа в `src/index.css`.

Важно: проверять актуальные коммиты, состав файлов, статусы Actions и Preview через GitHub/Vercel. Наличие кода в ветке не означает, что он опубликован в Apps Script или Production.

## Известные незавершённые направления
1. Полный аудит backend и семейной изоляции всех API действий.
2. Проверка параллельных/частично успешных операций в Google Sheets.
3. Полный регрессионный набор для счетов, переводов, целей, recurring и purchases.
4. Производительность: кэш/частота polling, число Sheets reads/writes, фактические latency.
5. Новый дизайн всех экранов и мобильная навигация.
6. Telegram: безопасная индивидуальная привязка, webhook/relay, read-only команды, уведомления.
7. Полный E2E на тестовой таблице и двух тестовых пользователях.
8. Ручная проверка на iPhone и desktop.
9. AI assistant — только после стабилизации основного приложения и отдельного согласования.
