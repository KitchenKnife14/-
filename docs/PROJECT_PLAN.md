# План завершения — «Бюджет для двоих»

## Принципы
- Сохранять архитектуру React + TypeScript + Google Sheets + Google Apps Script.
- В первую очередь достоверность финансовых данных и безопасность.
- Не публиковать Apps Script и не менять Production в рамках обычного этапа.
- Работать маленькими логическими изменениями и проверять каждое изменённое поведение.
- Все финансовые сценарии тестировать на отдельной тестовой таблице и вымышленных данных.

## P0 — Проверить текущую рабочую линию
1. Получить текущий HEAD ветки `audit/backend-upsert-guards`.
2. Проверить текущие GitHub Actions, статусы Vercel, открытые PR и diff.
3. Проверить локальные/удалённые изменения и не затереть чужую работу.
4. Разделить то, что находится в ветке, на что покрыто CI, что требует live test и что ещё не проверено.

Критерий готовности: имеется однозначный актуальный снимок исходников и проверок; все утверждения о тестах подтверждены реальными результатами.

## P1 — Финансовая безопасность и целостность
- Проверить auth/session lifecycle, password hashing, signup/signin/signout.
- Проверить семейную изоляцию для каждой API операции.
- Проверить каждую связь между транзакцией, счётом, категорией, целью, плановой покупкой и recurring payment.
- Проверить фильтры update/delete и защиту от неограниченной мутации.
- Проверить денежные значения: целые копейки, безопасный диапазон, отсутствие округлений и строковых чисел в некорректных местах.
- Проверить переводы: обе стороны, повтор, частичный сбой, редактирование и удаление.
- Проверить снятия/пополнения целей: баланс не ниже нуля, история и saved_kopecks совпадают.
- Проверить recurring confirm и purchase confirm на двойные нажатия и retry.
- Проверить откаты многошаговых операций.
- Проверить formula injection в Google Sheets при записи текста пользователя.
- Проверить блокировки и поведение при исключении после изменения части листов.

Критерий готовности: тесты покрывают положительные и отрицательные сценарии; финансовые инварианты проверяются на сервере; результаты не расходятся между Dashboard, Accounts, Budgets, Goals и Reports.

## P2 — Скорость
- Измерить фактические latency основных API actions.
- Записывать количество чтений и записей Google Sheets на действие.
- Проверить cache TTL и соответствие частоте обновления данных двух участников.
- Проверить batch request semantics и изоляцию ошибок каждого подзапроса.
- Проверить дублирующиеся запросы после авторизации и при смене маршрута.
- Изучить самый тяжёлый экран и оптимизировать только после измерений.
- Проверить Vite initial bundle и lazy loading существующих страниц.
- Проверить поведение при медленной сети, тайм-ауте и повторе.

Критерий готовности: есть baseline и сравнение после оптимизации; нет потери свежести финансовых данных ради кэширования.

## P3 — Дизайн-система и мобильная навигация
1. Завершить визуальные токены: фон, поверхности, границы, текст, акценты, состояния.
2. Стандартизировать кнопки, поля, карточки, modal, alerts, skeleton/loading/empty/error.
3. Переработать Layout и мобильную навигацию.
4. Обновить Dashboard.
5. Обновить Transactions и форму быстрого добавления операции.
6. Обновить Accounts, Budgets, Goals, Purchases, Recurring.
7. Обновить Calendar, Planning, Categories.
8. Обновить Reports, Analysis, Notifications.
9. Проверить все экраны на 375–390 px и desktop.
10. Выполнить доступность: фокус, контраст, touch target, reduced motion.

Критерий готовности: все экраны используют одну дизайн-систему, нет горизонтального переполнения, основные действия доступны большим пальцем, визуальные состояния единообразны.

Примечание: точная подгонка под прежний дизайн-референс ожидает ссылку или скриншоты владельца. До их получения реализуется цельный улучшенный предварительный стиль без заявления о совпадении с референсом.

## P4 — Telegram MVP
- Добавить таблицы Telegram links, link codes и update dedupe с проверкой заголовков.
- Добавить UI подключения Telegram и генерации одноразового кода.
- Код: криптографически случайный, связан с конкретным user_id/family_id, короткий TTL, одноразовый.
- Добавить webhook relay, который проверяет Telegram secret header и подписывает пересылку в Apps Script.
- Apps Script проверяет подпись, timestamp и replay protection.
- Сначала реализовать private-chat only: /start, /help, /link, /unlink, /today, /month, /budgets, /goals.
- Проверять права на каждую сводку; не доверять family_id из сообщения.
- Дедуплицировать update_id, поставить rate limit, безопасно экранировать вывод.
- Уведомления: бюджетные пороги 75/90/100%, регулярные платежи, цели; настройки opt-in.
- Не отправлять персональные данные в групповые чаты по умолчанию.
- Тестировать на тестовом боте и фиктивной семье.

Критерий готовности: тесты привязки/отвязки, чужого кода, истечения, повторного update, отсутствующих прав и ошибочных запросов; пользователь может отключить бота; секреты не попадают в клиент и Git.

## P5 — Сквозная проверка
- Два тестовых пользователя, одна тестовая семья.
- Проверить все операции на одном и втором аккаунтах.
- Проверить обновления между пользователями и свежесть.
- Прогнать всю матрицу основных сценариев.
- Проверить мобильное и desktop.
- Подготовить короткую инструкцию резервного копирования и восстановления.

Критерий готовности: нет блокирующих дефектов, все ключевые сценарии имеют тесты и подтверждены реальной проверкой на тестовой среде.

## P6 — AI помощник
Рассматривать только после P0–P5 и отдельного выбора модели/стоимости. Доступ только к данным семьи, read-only сначала, минимизация контекста, согласие пользователя, лимиты и серверная проверка. Финансовые изменения — только с явным подтверждением.

## Release gates
- Ветка и PR готовы к review.
- GitHub Actions зелёный.
- Preview проверен.
- Отдельная тестовая Google Sheet проверена.
- Есть резервная копия перед любой миграцией схемы.
- Отдельное разрешение владельца получено до публикации Apps Script, смены Production конфигурации, подключения настоящего семейного листа или Telegram webhook.
