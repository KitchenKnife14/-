# Family Cash — список будущих улучшений

Этот список содержит идеи, которые можно реализовать после завершения основных макроэтапов и стабилизации текущего приложения. Это не обязательства и не часть текущей приёмки. Приоритеты можно пересматривать; ничего из списка не должно задерживать исправление ошибок и завершение текущего плана.

## Возможные функции

| Идея | Что даст | Статус |
|---|---|---|
| AI-помощник по семейным финансам | Отвечать на вопросы о расходах, доходах, бюджетах и целях на основе данных семьи | Отложено |
| Сканирование чеков | Фото чека → распознавание магазина, даты, позиций, суммы и возможной категории → подтверждение пользователем перед записью | Отложено |
| Автоматическая категоризация операций | Предлагать категорию по описанию и истории похожих операций | Отложено |
| Поиск необычных расходов | Показывать заметные отклонения от привычных расходов | Отложено |
| Прогноз бюджета до следующей зарплаты | Оценивать остаток доступных денег и ожидаемые обязательные платежи | Отложено |
| Голосовой ввод операций | Добавлять доходы и расходы голосом с подтверждением перед сохранением | Отложено |
| Напоминания об автоплатежах | Напоминать о регулярных платежах и приближении даты списания | Отложено |
| Календарь зарплат и лимиты | Показывать даты поступлений и предупреждать о приближении лимитов | Отложено |
| Импорт банковских выписок | Загружать выписку и предлагать распознанные операции для проверки и импорта | Отложено |
| Расширенные финансовые отчёты | Сравнивать периоды, категории и участников, показывать динамику | Отложено |
| Резервное копирование и восстановление | Упростить создание и проверку резервной копии семейных данных | Отложено |
| **Восстановление пароля по email** | Если пользователь забыл пароль — запросить письмо, перейти по ссылке или ввести код и задать новый пароль | **Необязательное улучшение** |

## Условия реализации

- Сначала завершить основные макроэтапы и закрыть обязательные исправления.
- Не подключать нейросети, OCR и внешние платные сервисы без отдельного решения пользователя.
- При сканировании чека и AI-категоризации не записывать распознанные данные автоматически: сначала показать пользователю черновик и дать подтвердить.
- Не менять существующие финансовые записи и алгоритмы балансов ради добавления необязательных функций.
- Учитывать ограничения проекта: Google Sheets + Apps Script + Vercel + GitHub; Supabase не использовать.

## Приоритет

Список не является очередью обязательных работ. AI-помощник, сканирование чеков и восстановление пароля остаются идеями на будущее. Восстановление пароля можно реализовать раньше только если это станет практической необходимостью и не будет мешать завершению текущего плана.
