# Подключение Google Sheets — безопасный запуск

Эта инструкция рассчитана только на отдельную тестовую копию таблицы. Не подключайте тестовый Apps Script к основной таблице с реальными семейными данными. Все пункты ниже выполняются в тестовом проекте; Production не обновлять.

## 0. Подготовить резервную копию

1. Откройте Google Sheets и убедитесь, что выбрана нужная таблица.
2. Создайте копию таблицы через **Файл → Создать копию**. Назовите её, например, «Семейный бюджет — резервная копия».
3. Не открывайте доступ к таблице по ссылке. Саму таблицу должны видеть только вы и те, кому действительно нужен доступ к ней.
4. До успешного теста используйте только вымышленные тестовые данные.

## 1. Создать Apps Script

1. В исходной таблице выберите **Расширения → Apps Script**.
2. Откройте Apps Script именно из созданной тестовой копии таблицы: **Расширения → Apps Script**. Не открывайте Apps Script из исходной рабочей таблицы.
3. Используйте исходники только из рабочей ветки [ispravleniya](https://github.com/KitchenKnife14/-/tree/ispravleniya), прежде всего `google-apps-script/Code.gs` и `google-apps-script/appsscript.json`. Не берите код из старых веток `work/final-features-performance` или `main`.
4. Замените содержимое `Code.gs` кодом из этой ветки. Manifest из репозитория задаёт `Europe/Moscow` и V8; его наличие в Git ещё не означает, что он уже синхронизирован с Apps Script-проектом.
5. Скрипт должен быть привязан именно к тестовой копии. Он использует активную таблицу, а не отдельный ID.
5. При первом запросе листы создаются автоматически. Скрытый лист `_auth` содержит email и хеши паролей; не делайте его видимым и не публикуйте таблицу.



**Что меняется в API v11:** в листах `transactions` и `recurring_payments` добавляется только новый конечный столбец `responsible_user_id`, если все существующие заголовки совпадают с началом ожидаемой структуры. Листы `telegram_links` и `telegram_link_codes` создаются автоматически при первом обращении к Telegram RPC/webhook. Код не очищает и не переставляет существующие строки. Если заголовки не совпадают, он остановится с ошибкой вместо небезопасной миграции. Это обновление схемы Google Sheets, а не перенос данных из другого backend.

## 2. Развернуть веб-приложение

### Номер версии Apps Script и API_VERSION — разные счётчики

Google самостоятельно назначает номер версии Apps Script при создании новой версии. `API_VERSION` — внутренняя константа приложения. Они не обязаны совпадать. Не создавайте пустые промежуточные версии и не меняйте код только ради совпадения этих чисел. При реальном обновлении тестового развёртывания создайте одну новую версию с проверенным кодом. URL существующего тестового deployment сохраняйте.

1. Если тестовое веб-приложение уже развёрнуто (его URL указан в Preview-переменной Vercel), откройте **Развернуть → Управление развертываниями** и нажмите карандаш у этого развертывания. Так сохранится прежний URL `/exec`, который уже подключён к Preview.
2. Если подходящего тестового развертывания ещё нет, выберите **Новое развертывание**. Тип: **Веб-приложение**.
3. Выберите версию **Новая версия**. Выполнять от имени: **вас** — владельца таблицы.
4. Для доступа выберите вариант, позволяющий сайту обращаться к API без входа в Google-аккаунт. Для самостоятельной регистрации в приложении это может потребовать доступ «Все». В таком случае адрес API будет публично доступен, но операции должны проходить собственную авторизацию приложения. Это повышает требования к проверке безопасности; не используйте реальные финансовые данные до завершения тестов.
5. Нажмите **Развернуть**, пройдите запрашиваемую авторизацию Google и убедитесь, что URL веб-приложения заканчивается на `/exec`. Если пришлось создать новое развертывание, его URL нужно будет указать в Preview-переменной Vercel.
6. Не включайте `DEBUG_INFO` (`showInfo()`) на публичном веб-развёртывании: эта настройка добавляет имя таблицы в GET-ответ. Проверяйте привязку тестовой таблицы внутри редактора Apps Script и через безопасные журналы выполнения. Обычный `/exec` должен возвращать только статус и версию API. Если есть сомнение, что проект привязан к тестовой копии, не продолжайте развёртывание.

## 3. Подключить тестовую сборку сайта (Vercel)

1. Используйте основной Vercel-проект **`-`** (именно к нему привязан адрес `nikita-aa7c.vercel.app`). Не создавайте новый Vercel-проект: `--akmd`, `--klm2` и `--rwg9` — дублирующие/черновые проекты без основного адреса.
2. В основном проекте переменная `VITE_GOOGLE_APPS_SCRIPT_URL` уже настроена только для **Preview** и указывает на тестовую таблицу. Если вы обновили существующее Apps Script-развертывание, URL не меняется и переменную трогать не нужно.
3. Не добавляйте тестовый URL в **Production** и не подключайте Preview к таблице с реальными семейными данными.
4. Используйте Preview только из ветки `ispravleniya`, после успешного CI и проверки, что `VITE_GOOGLE_APPS_SCRIPT_URL` указывает на тестовый Apps Script. Не переключайте Production.
5. Если пришлось создать новое Apps Script-развертывание и URL изменился, замените значение Preview-переменной `VITE_GOOGLE_APPS_SCRIPT_URL`, сохраните и создайте новый Preview deployment. Vite встраивает `VITE_*` переменные в клиентский JavaScript во время сборки.
6. Проверьте в Preview регистрацию и вход только на тестовой таблице и вымышленных данных.

**Важно:** если `VITE_GOOGLE_APPS_SCRIPT_URL` отсутствует, сборка интерфейса всё равно может завершиться успешно, но запросы авторизации и данных будут завершаться ошибкой «Не настроен VITE_GOOGLE_APPS_SCRIPT_URL». Не считайте открывшуюся страницу входа доказательством подключения backend.

Для локального запуска скопируйте `.env.example` в `.env` и укажите тестовый URL. Не добавляйте URL, токены или другие секреты в Git.

## 4. Обязательный чек-лист до подключения реальных данных

Проверять только на тестовых аккаунтах и суммах:

- [ ] Регистрация двух разных пользователей и вход/выход.
- [ ] Первый пользователь создаёт семью и видит код приглашения.
- [ ] Второй пользователь присоединяется по коду.
- [ ] Оба пользователя видят общие операции и изменения после обновления страницы.
- [ ] Посторонний третий пользователь не видит семейные данные и не может записывать данные в чужую семью.
- [ ] Создание, редактирование и удаление дохода/расхода.
- [ ] Категории и подкатегории создаются без дубликатов.
- [ ] Повторяющиеся платежи: подтверждение, повторный запрос, конечная дата.
- [ ] Цели: пополнение, снятие, история и удаление цели.
- [ ] Планирование, бюджеты, покупки, отчёты и CSV.
- [ ] Корректные даты в часовом поясе Europe/Moscow.
- [ ] Проверка на телефоне и компьютере.
- [ ] Обновление страницы и повторный вход не теряют данные.

Регрессионные тесты в GitHub проверяют часть логики в имитированной среде. Они не заменяют реальный тест Google Apps Script, браузерных запросов и двух устройств.

## 5. Обновление и откат

- После каждого изменения `Code.gs` сначала проверьте код и manifest, затем обновляйте только тестовое веб-развёртывание через **Развернуть → Управление развертываниями → карандаш → Версия → Новая версия → Развернуть**. Простого сохранения редактора недостаточно. Production deployment не редактировать.
- Перед обновлением сделайте копию таблицы.
- При ошибке переключите развертывание на предыдущую рабочую версию Apps Script и верните прежний URL/переменную окружения тестового сайта.
- Основной Vercel-проект сайта — `-`. Его Preview подключён к тестовой таблице; Production не переключать, пока не завершён экспорт и перенос существующих данных. Переменная `VITE_GOOGLE_APPS_SCRIPT_URL` в Preview не должна указывать на рабочую таблицу.
- Не объединяйте `ispravleniya` в `main` и не переключайте Production, пока аудит, тестовый Apps Script, двухпользовательские сценарии, Telegram и сохранность основной таблицы не проверены отдельно. Совпадение номера версии Apps Script с `API_VERSION` не является условием релиза.

## Ограничения текущей версии

Это подготовка к первому развёртыванию, а не подтверждение production-безопасности. До реального использования отдельно нужно оценить защиту от перебора паролей, надёжность хеширования паролей, лимиты Google Apps Script и поведение при одновременной записи. Не храните в таблице банковские реквизиты, пароли от сторонних сервисов или иные секреты.
