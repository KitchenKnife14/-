# Подключение Google Sheets — безопасный запуск

Эта инструкция рассчитана на отдельную тестовую таблицу **«Семейный бюджет - тест»**. Не используйте рабочую таблицу с личными данными до завершения проверок.

## 0. Подготовить резервную копию

1. Откройте Google Sheets и убедитесь, что выбрана именно тестовая таблица **«Семейный бюджет - тест»**.
2. Создайте копию таблицы через **Файл → Создать копию**. Назовите её, например, «Семейный бюджет — резервная копия».
3. Не открывайте доступ к таблице по ссылке. Саму таблицу должны видеть только вы и те, кому действительно нужен доступ к ней.
4. До успешного теста используйте только вымышленные тестовые данные.

## 1. Подготовить отдельный тестовый Apps Script — НЕ заменять существующий код

**СТОП: файл `google-apps-script/Code.gs` в этой ветке содержит 438 строк и является новой, сокращённой реализацией API. Он не является патчем или полной копией существующего Apps Script проекта. Если в вашем редакторе сейчас находится `Code.gs` примерно на 1700 строк, НЕ заменяйте его содержимое кодом из репозитория.** Такая замена может удалить существующие функции и обработчики.

До завершения сверки исходного проекта нельзя вставлять этот файл поверх существующего `Code.gs`, добавлять его вторым `.gs`-файлом в тот же проект (возможны конфликты глобальных имён) или обновлять существующее развертывание.

Безопасная проверка требует отдельной тестовой копии таблицы и отдельного тестового Apps Script проекта, в котором нет рабочего кода. Сначала необходимо сверить полный исходный Apps Script (все `.gs`-файлы, библиотеки, триггеры и настройки) с реализацией в этой ветке и составить карту переноса. Если отдельный чистый тестовый проект ещё не подготовлен, остановитесь: не изменяйте текущий проект.

Файл API в этой ветке можно использовать только после такой сверки и только в отдельной тестовой среде. Он использует `SpreadsheetApp.getActiveSpreadsheet()`, поэтому должен быть привязан к тестовой таблице, а не к рабочей.

## 2. Развертывание — заблокировано до сверки кода

Не обновляйте существующее тестовое развертывание: оно может быть связано с Apps Script проектом, в котором находятся ваши 1700 строк. Не создавайте новую версию этого проекта и не меняйте его URL.

Сначала требуется получить полный исходный код текущего Apps Script и сопоставить каждую функцию, триггер, точку входа и используемую настройку с кодом миграции. Только после этого можно подготовить отдельный тестовый проект и проверить API на синтетических данных. Пока сверка не завершена, живой API-тест не запускается.

## 3. Подключить тестовую сборку сайта

1. В Vercel откройте проект → **Settings → Environment Variables**.
2. Добавьте `VITE_GOOGLE_APPS_SCRIPT_URL` со значением URL `/exec` только для окружения **Preview**. Не добавляйте и не заменяйте эту переменную в Production.
3. Не удаляйте и не заменяйте другие переменные окружения, пока они не проверены.
4. Сначала используйте отдельный deploy preview/тестовый сайт, а не опубликованный сайт. Если тестового сайта нет, его нужно подготовить до переключения production.
5. Создайте новый Preview deployment и проверьте в нём регистрацию, вход и основные операции. Убедитесь, что деплой собран из ветки `migration/google-sheets`.

Для локального запуска скопируйте `.env.example` в `.env` и укажите тестовый URL. Не добавляйте URL, токены или другие секреты в Git.

## 4. Обязательный чек-лист до подключения реальных данных

Проверять только на тестовых аккаунтах и суммах:

- [ ] Регистрация двух разных пользователей и вход/выход.
- [ ] Первый пользователь создаёт семью и видит код приглашения.
- [ ] Второй пользователь присоединяется по коду.
- [ ] Оба пользователя видят общие операции и изменения после обновления страницы.
- [ ] Посторонний третий пользователь не видит семейные данные и не может записывать данные в чужую семью.
- [ ] Создание, редактирование и удаление дохода/расхода.
- [ ] Категории и подкатегории создаются без дубликатов.
- [ ] Повторяющиеся платежи: подтверждение, повторный запрос, конечная дата.
- [ ] Цели: пополнение, снятие, история и удаление цели.
- [ ] Планирование, бюджеты, покупки, отчёты и CSV.
- [ ] Корректные даты в часовом поясе Europe/Moscow.
- [ ] Проверка на телефоне и компьютере.
- [ ] Обновление страницы и повторный вход не теряют данные.

Регрессионные тесты в GitHub проверяют часть логики в имитированной среде. Они не заменяют реальный тест Google Apps Script, браузерных запросов и двух устройств.

## 5. Обновление и откат

- После каждого изменения `Code.gs` создавайте новую версию через **Развернуть → Управление развертываниями → Изменить → Новая версия**. Простого сохранения редактора недостаточно для обновления уже опубликованной версии.
- Перед обновлением сделайте копию таблицы.
- При ошибке переключите развертывание на предыдущую рабочую версию Apps Script и верните прежний URL/переменную окружения тестового сайта.
- Не объединяйте ветку `migration/google-sheets` в `main` и не переключайте production, пока пользователь не проверит тестовый сайт и не подтвердит готовность.

## Ограничения текущей версии

Это подготовка к первому развёртыванию, а не подтверждение production-безопасности. До реального использования отдельно нужно оценить защиту от перебора паролей, надёжность хеширования паролей, лимиты Google Apps Script и поведение при одновременной записи. Не храните в таблице банковские реквизиты, пароли от сторонних сервисов или иные секреты.
